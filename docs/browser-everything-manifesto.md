# ブラウザで何でもやる派宣言

## はじめに

私は、ブラウザで何でもやる。

これは「ブラウザだけで全部のソフトウェアを作る」という意味ではない。

**成果を得るための入口を、ブラウザに集約する。**

コードを書く。
Issueを作る。
AIに相談する。
調べる。
データを見る。
レビューする。
Deployする。
音を聴く。
画面を確認する。
成果物を公開する。

そのすべてを、できるだけ自然な言葉から始める。

GitHubとChatGPTとブラウザがあれば、かなりのことができる。

私は、このやり方を「ブラウザで何でもやる派」と呼ぶ。

---

## 富豪プログラミング

昔のプログラミングは、プログラマがコンピュータに細かく命令する仕事だった。

ファイルを作る。
コードを書く。
依存関係を調べる。
コマンドを覚える。
エラーを読む。
修正する。
Buildする。
Deployする。

ひとつひとつは正しい。

しかし、人間が本当に欲しいのはコマンドではない。

**成果である。**

「GitHubにこの仕組みを作って」
「このデータを分析して」
「このIssueを潰して」
「この画面を公開して」
「このプロジェクトを整理して」

本来はこちらを言いたい。

そこで、プログラミングの一部をAIに渡す。

これは単なる自動化ではない。

**計算資源・ストレージ・AI・クラウド・OSSを大量に使い、人間は目的と判断に集中する。**

私はこれを、富豪プログラミングと呼びたい。

節約して一行ずつ書くのではなく、利用できる資源を贅沢に組み合わせる。

---

## 自然言語をUIにする

GUIにはボタンがある。

CLIにはコマンドがある。

APIにはエンドポイントがある。

しかしAI時代には、その上にもう一つのUIがある。

**自然言語である。**

「これを調べて」
「比較して」
「Issueにして」
「実装して」
「テストして」
「pushして」
「Deployして」
「直して」

この言葉を、AIがGitHubやブラウザや開発環境の操作へ変換する。

つまり、

```text
自然言語
   ↓
AI
   ↓
ツール
   ↓
GitHub / Browser / Cloud
   ↓
成果
```

となる。

人間はツールの使い方を全部覚えなくてもよい。

重要なのは、**何を作りたいのかを言葉にすること**である。

---

## ChatGPTアプリを司令塔にする

ChatGPTを単なる質問箱として使わない。

プロジェクトの司令塔として使う。

会話する。

考える。

調べる。

ファイルを扱う。

コードを作る。

GitHubを見る。

Issueを作る。

Pull Requestを確認する。

そして、必要な操作を実行する。

人間はブラウザ上で成果を確認する。

このときChatGPTはIDEそのものではない。

**IDE、検索、ターミナル、GitHub、ドキュメント、ブラウザ操作を横断する自然言語インターフェース**になる。

---

## GitHubを作業台にする

GitHubは単なるコード置き場ではない。

プロジェクトのCanonにする。

```text
Repository
├── Code
├── Issue
├── PR
├── Actions
├── Pages
├── Releases
└── Data / Docs
```

ここに成果を残す。

AIとの会話は流れていく。

しかし、GitHubに残した成果は次のAIや次の自分が利用できる。

だから、

**会話 → 成果物 → GitHub**

という流れを作る。

---

## ブラウザは世界への窓

ブラウザには、ほぼすべての仕事の入口がある。

GitHub。
Google。
データベース。
クラウド。
ドキュメント。
SNS。
ニュース。
EC。
分析画面。
Deploy画面。
AI。

だからブラウザを「Webを見る道具」だけに限定しない。

**世界に対する操作面**として扱う。

コードを書く場所もブラウザ。

Issueを管理する場所もブラウザ。

成果を見る場所もブラウザ。

AIに仕事を頼む場所もブラウザ。

---

## Orochi

この思想をブラウザ側から支えるのがOrochiである。

Orochiはタブ管理ソフトではない。

**プロジェクトという単位でブラウザを組織する。**

一つのプロジェクトには、複数の頭がある。

```text
Repo
Issue
PR
Action
Deploy
Chat
Data
World
```

これを一つのProject Contextとして扱う。

```text
1 Project
    ↓
1 Context
    ↓
1 Browser Group
```

ユーザーが「このプロジェクトを見せて」と言えばよい。

Orochiが必要な場所を開く。

AIが必要なものを整理する。

ブラウザは、そのプロジェクトの現在地を映す。

---

## CRXは薄くする

Chrome Extensionに全部を詰め込まない。

CRXはブラウザの目と手だけを担当する。

認証。
データ。
AI。
GitHub操作。

これらをExtensionに持たせない。

```text
CRX
 ↓
local runtime
 ↓
Orochi Core
 ↓
GitHub / AI / other tools
```

ブラウザはProjection。

Coreが意味を持つ。

GitHubがCanon。

AIがConductor。

この分離によって、ブラウザを軽く保つ。

---

## 「コマンドを覚えない」という贅沢

CLIが嫌いなのではない。

CLIは強い。

しかし、CLIの操作方法を人間が全部覚える必要はない。

AIに、

「このIssueを調べて修正して」

と言えばよい。

AIが必要なら、

```text
gh issue view
gh issue edit
git switch
git commit
git push
gh pr create
```

のような操作を組み立てる。

人間はコマンドの暗記から解放される。

CLIは消えない。

**CLIはAIの手になる。**

---

## 成果物中心

自然言語開発で重要なのは、会話量ではない。

成果物である。

```text
会話
 ↓
判断
 ↓
操作
 ↓
Artifact
 ↓
GitHub
```

Artifactには、

- code
- md
- json
- csv
- image
- audio
- dashboard
- release
- deployed page

がある。

「話した」だけでは仕事は終わらない。

**残ったものが仕事である。**

---

## 薄い本

この宣言は薄い。

厚いマニュアルを作ることが目的ではない。

むしろ、厚いマニュアルをAIに読ませ、人間は薄い入口から入る。

```text
人間
 ↓
自然言語
 ↓
AI
 ↓
Tools
 ↓
Artifacts
 ↓
GitHub
 ↓
世界
```

この一本の流れがあればよい。

細かい操作は、その都度AIに生成させる。

必要なら調べる。

必要ならコードを書く。

必要ならツールを増やす。

必要なら自動化する。

---

## 何でもブラウザでやる

「何でもブラウザでやる」は、ブラウザ以外を否定する思想ではない。

むしろ逆である。

裏側では、

- Git
- GitHub API
- GitHub Actions
- Deno
- TypeScript
- MCP
- CLI
- Cloud
- Database
- AI

を自由に使う。

ただし、人間がそれらを一つずつ操作する必要を減らす。

**複雑さは裏側へ置く。**

表側は、

**「こうしたい」**

でよい。

---

## 結論

プログラミングの中心は、コードを書くことから成果を作ることへ移っている。

AIはコードを書く。

GitHubは成果を保存する。

Actionsは実行する。

Cloudは公開する。

ブラウザは世界との接点になる。

そしてChatGPTは、それらを自然言語で束ねる。

だから私は、

**ブラウザで何でもやる派**

を宣言する。

コマンドを覚えるために働くのではない。

ツールを操作するために働くのでもない。

**作りたいものを言葉にして、成果を手に入れる。**

それが、これからの富豪プログラミングである。
